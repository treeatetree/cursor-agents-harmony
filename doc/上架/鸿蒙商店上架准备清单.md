# 鸿蒙商店上架准备清单

更新日期：2026-08-19  
适用范围：中国大陆华为应用市场 + 首批海外 AppGallery  
当前主体：个人开发者，已实名认证，尚未创建 AGC 应用  
当前建议：V1 免费无内购，海外小范围先行，中国区完成专项合规确认后再提交

## 一、现在最应该关注的事情

### P0：先处理品牌、应用名和包名

这是当前最先要解决的问题。在它解决前，不要创建正式 AGC 应用、申请软件著作权或提交 APP 备案。

当前工程直接使用：

- 应用名：`Cursor Agents`
- 包名：`com.brian.cursor.mobile`
- 描述：`Cursor Cloud Agents 鸿蒙原生客户端`

但目前没有 Cursor 对商标、应用名称、第三方客户端公开分发和商业化的书面授权。华为审核规则禁止应用名称、图标或内容让用户误以为产品由第三方官方提供。

需要完成：

- [ ] 确定一个不含 Cursor 商标的独立中英文品牌名
- [ ] 确定新的正式 bundleName，并移除 `cursor`
- [ ] 重新设计独立图标，避免与 Cursor 官方产品视觉近似
- [ ] 向 Cursor 书面确认第三方客户端分发、用户自带 API Key、收费和品牌引用边界
- [ ] 仅在取得许可后，以“兼容/连接 Cursor 服务”的事实性方式描述第三方服务
- [ ] 品牌、bundleName、软著名称、AGC 名称和 APP 备案名称一次锁定并保持一致

如果先用当前名字创建 AGC、申请软著或备案，之后再改名，会产生应用身份、证书、软著和备案材料不一致的问题。

### P0：明确中国区是否具备可上架条件

应用直接把用户的 API Key、仓库信息、prompt、对话、代码任务和图片发送到境外 `api.cursor.com`。当前没有自建后端，也无法自行切换为大陆数据面。

中国区提交前必须确认：

- [ ] Cursor 实际数据处理地域
- [ ] Cursor 对 prompt、代码、仓库和图片的保存期限及删除机制
- [ ] 是否能够提供适用于中国用户的数据处理和跨境依据
- [ ] 是否需要个人信息保护影响评估、单独同意或其他出境机制
- [ ] 该产品是否被认定为向境内公众提供生成式 AI 功能
- [ ] 是否需要算法备案或地方登记
- [ ] 是否适用生成合成内容显式/隐式标识
- [ ] 是否需要真实身份核验、投诉举报入口及 AI 专项审核材料

建议向华为提交正式工单，附产品说明和数据流图，取得书面口径。若 Cursor 无法提供必要的数据处理信息，应暂缓中国区，而不是仅靠隐私政策文字规避风险。

### P0：补齐隐私产品能力，而不只是写一份政策

当前工程的安全基础不错，但合规产品能力不足。

已有能力：

- API Key 使用 HUKS AES-256-GCM 加密
- Agent 业务缓存使用 AES-GCM 加密
- 日志会遮盖 `crsr_…` 和 Bearer Token
- 相册使用系统 Photo Picker，无需申请整个相册权限
- 剪贴板读取通过 PasteButton 临时授权
- 没有广告、统计、支付或第三方运行时 SDK

当前高风险缺口：

- 没有首次启动隐私同意
- 没有公开隐私政策和用户协议入口
- “无需担心安全和隐私问题”的文案属于不准确的绝对化承诺
- “清除 Key”没有完整删除头像、MCP 配置、诊断文件、Widget 等全部本地数据
- MCP `envVars`、headers 等内容可能明文保存在 Preferences
- 诊断日志默认开启，可能记录仓库名和错误元数据
- 邮箱、Key 名称、显示名仍可能明文保存

提交前必须完成：

- [ ] 发布中英文隐私政策、用户协议、支持页和数据删除说明
- [ ] 首次联网前提供同意和拒绝选项，不默认勾选
- [ ] 设置页长期提供隐私政策、用户协议、撤回同意和清除本机数据入口
- [ ] 提供“已收集个人信息清单”和“第三方共享个人信息清单”
- [ ] 用事实性描述替换“无需担心安全和隐私问题”
- [ ] 默认关闭诊断，或在用户明确同意后开启
- [ ] 加密或取消持久化 MCP env/header、邮箱、Key 名称等敏感数据
- [ ] 完整清除 Key、账号资料、缓存、草稿、头像、MCP 配置、诊断、未读、Widget 和实况数据
- [ ] 明确清除本机数据不等于注销 Cursor 账号
- [ ] AGC 隐私标签、权限理由、应用实际行为和隐私政策保持一致

### P0：建立真正的发布包和签名链路

当前虽然存在约 4.5 MB 的 signed HAP，但审计确认它仍是 debug 构建；当前脚本默认也是 debug，并且只执行 `assembleHap`，尚无正式 App Pack 流水线。

需要完成：

- [ ] 品牌与 bundleName 锁定后，在 AGC 创建 HarmonyOS 应用
- [ ] 使用云管理签名，或申请并妥善备份发布证书与 Release Profile
- [ ] 私钥、Profile 和口令不得进入仓库或日志
- [ ] 增加正式 release App Pack/HAP 构建路径
- [ ] 自动确认最终产物不是 debug 签名或 debug build
- [ ] 固化 versionCode 递增和 versionName 管理
- [ ] Release 混淆后回归 HUKS、SSE、序列化、Widget、WebView 和实况窗
- [ ] 验证全新安装、覆盖升级、卸载重装和签名一致性
- [ ] 确认 LiveView 权益；未开通则从首发包移除 `LiveViewLockAbility`
- [ ] 复核 `EntryFormAbility exported: true` 是否必要

## 二、当前最有风险的问题

### 风险 1：第三方品牌与知识产权

风险等级：极高，可能直接驳回。

当前名称、包名和描述会使用户认为这是 Cursor 官方客户端。仅写“非官方”并不能自动获得商标使用权。若没有书面授权，优先采用独立品牌。

### 风险 2：中国区生成式 AI 与境外服务合规

风险等级：极高，可能不是简单改代码能解决。

产品通过境外 Cursor Cloud Agents 生成代码、文本和任务结果。是否需要算法登记、内容标识、实名和专项材料，需要华为及专业合规确认。应用自身无法控制 Cursor 的服务器地域。

### 风险 3：隐私声明和实际行为不一致

风险等级：极高，容易在自动检测或人工审核中失败。

当前应用会传输和缓存敏感业务内容，但没有正式隐私同意和政策入口，且现有文案过度承诺。政策、AGC 标签和代码必须逐项一致。

### 风险 4：没有真正可提审的 Release 产物

风险等级：高，属于工程阻塞。

现有 signed HAP 仍为 debug。发布证书、Profile、正式 `.app`/App Pack、release 安装与升级证据均未完成。

### 风险 5：个人开发者收费资格不确定

风险等级：高，但首版免费可规避。

华为通用协议存在个人开发者和付费产品表述，但中国区联运公开入口仍要求企业开发者。是否能开通付费下载、IAP 或订阅，应以当前个人账号控制台和华为工单书面答复为准。

在资格确认前不要投入支付开发。

### 风险 6：审核员无法体验核心功能

风险等级：高。

应用必须使用 Cursor API Key，且核心功能依赖 Cursor 账号、套餐和代码仓库。需要准备完全独立的审核账号、测试 Key、测试仓库和可重复演示的 Agent 流程。不得把个人真实 Key 或私有仓库交给审核员。

### 风险 7：海外版本实际没有完成国际化

风险等级：中高。

当前绝大部分 UI 文案硬编码为中文，只有少量字符串进入资源文件。海外首发至少需要完整英文 UI、商店材料和隐私文本；目标国家还可能要求当地语言法律文本。

### 风险 8：适配声明大于现有测试证据

风险等级：中高。

工程声明支持 phone 和 tablet，但现有证据主要来自 Pura X Max。尚需覆盖普通直板手机、普通平板、最低 API 12、目标 API 24、大字体、无障碍、折叠切换和 Release 混淆。

## 三、首发收费模式建议

### 方案 A：免费无内购

推荐首发采用。

优点：

- 不需要商户认证和支付 SDK
- 不受个人付费资格不确定性的阻塞
- 审核面最小
- 可以先验证海外分发、中国区备案、兼容性和隐私

注意：最初免费的同一商品页通常不能以后直接变成付费下载，但可以在取得资格后增加合规 IAP。

### 方案 B：一次性付费下载

首发不推荐。

需要商户服务、税务与收款资料、付费协议、版权保护、权益校验和沙盒测试。用户下载应用后还需要单独购买 Cursor 套餐，容易产生价值和收费关系不清的问题。

### 方案 C：免费加 IAP 或订阅

适合作为第二阶段。

需要：

- 商户服务及付费协议
- IAP API 和商品配置
- 服务端订单验签与事件通知
- 补单、恢复购买、退款和过期处理
- 订阅取消与管理入口
- 沙盒测试
- 更完整的隐私和客服体系

若只是一次性专业功能解锁，优先非消耗型 IAP；只有持续提供云服务或持续更新权益时才使用订阅。

## 八、建议执行顺序

### 第 1 阶段：身份和可行性

1. 锁定独立品牌、中文名、英文名和 bundleName。
2. 获取 Cursor 对分发和商业模式的书面意见。
3. 向华为提交品牌、个人付费资格、中国区 AI 和跨境数据工单。
4. 决定海外首批国家，以及中国区是否继续同期推进。

### 第 2 阶段：合规产品化

1. 建立数据清单和数据流图。
2. 完成隐私政策、用户协议和支持页面。
3. 实现首次同意、长期入口和完整本地数据清除。
4. 修复 MCP 明文、诊断默认开启和绝对化隐私文案。
5. 准备软著和 APP 备案。

### 第 3 阶段：发布工程

1. 创建 AGC 应用。
2. 建立 Release 签名和正式 App Pack/HAP 流水线。
3. 完成版本管理和 release 混淆回归。
4. 处理 LiveView 权益和 exported 扩展。

### 第 4 阶段：适配和测试

1. 完成 API 12–24、手机、平板和折叠屏矩阵。
2. 完成英文国际化和无障碍。
3. 跑完 Hypium、API 冒烟、22 项真机验收和 AGC 云兼容测试。
4. 准备审核专用账号、Key、仓库和操作说明。

### 第 5 阶段：材料和发布

1. 生成各语言商店文案、图标和截图。
2. 填写隐私、权限、年龄分级、备案、资质和 AI 材料。
3. 先走指定设备、邀请测试或公开测试。
4. 分别提交首批海外国家和中国区。
5. 首版稳定后，后续升级再使用 7 天分阶段发布。
